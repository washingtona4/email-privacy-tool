## How This Tool Works

This tool captures and analyzes all network traffic generated by each email provider during three phases of use: account creation, passive idle usage, and active email usage. It works by routing your browser traffic through mitmproxy, which intercepts and logs every HTTP and HTTPS request the provider makes — including requests to third-party services the provider may not disclose.

```
Your Browser → mitmproxy (intercepts + logs everything) → Email Provider's Servers
```

Wireshark runs alongside mitmproxy to capture raw packet-level data. After each experiment, the analysis scripts classify every domain contacted, flag known trackers, quantify metadata exposure, and assess whether encryption claims hold up.

**Everything runs inside a Virtual Machine (VM).** This ensures:
- A clean, identical environment for every experiment
- No contamination from your personal browsing history or background apps
- Full reproducibility across all four team members
- The ability to restore to a known-good state before each test

## VM Setup

Do this once before anything else. One team member should complete this entire section, then export and share the VM with the rest of the team (see [Sharing the VM With Teammates](#sharing-the-vm-with-teammates)).

### Step 1: Download and Install VirtualBox
Go to https://www.virtualbox.org and download the installer for your operating system (Windows, Mac, or Linux). Install it like any normal application.

### Step 2: Download Ubuntu
Go to https://ubuntu.com/download/desktop and download **Ubuntu 22.04 LTS**. The file is around 5GB so start this download early.

### Step 3: Create the VM
- Open VirtualBox and click **New**
- Name it `email-privacy-vm`
- Select the Ubuntu ISO you downloaded as the boot disk
- Assign at least **4GB RAM** and **2 CPU cores**
- Create a virtual hard disk of at least **25GB**
- Boot the VM and complete the Ubuntu installation wizard

### Step 4: Install System Tools Inside the VM
Open a terminal inside the Ubuntu VM and run:
```bash
sudo apt-get update
sudo apt-get install -y wireshark tshark python3 python3-pip git curl
```

When prompted during the Wireshark install, select **Yes** to allow non-superusers to capture packets.

### Step 5: Install mitmproxy
```bash
pip3 install mitmproxy
```

Verify it installed correctly:
```bash
mitmdump --version
```

### Step 6: Configure Your Browser Proxy
- Open **Firefox** inside the VM
- Go to Settings → Network Settings → Manual proxy configuration
- Set **HTTP Proxy** to `127.0.0.1`, Port `8080`
- Check **"Also use this proxy for HTTPS"**
- Click OK

### Step 7: Install the mitmproxy CA Certificate
This is the most important step. Without this, mitmproxy cannot read HTTPS traffic.

1. Start mitmproxy in a terminal:
   ```bash
   mitmdump --listen-port 8080
   ```
2. Open Firefox and navigate to `http://mitm.it`
3. Click the **Linux** option and download the certificate file
4. In Firefox go to Settings → Privacy & Security → View Certificates → Authorities tab → Import
5. Select the downloaded certificate file
6. Check **"Trust this CA to identify websites"**
7. Click OK and restart Firefox
8. Verify it works by visiting any HTTPS site — you should see the request appear in the mitmproxy terminal

### Step 8: Take Your clean-baseline Snapshot
Before doing anything else, save the VM state. This is your recovery point if anything goes wrong.

In VirtualBox with the VM running:
- Go to **Machine → Take Snapshot**
- Name it `clean-baseline`
- Click OK

## Tool Installation

After completing VM setup, clone the repo and run the setup script inside the VM.

### Step 1: Clone the Repository
```bash
git clone https://github.com/yourteam/email-privacy-tool
cd email-privacy-tool
```

### Step 2: Run Setup
```bash
chmod +x setup.sh
./setup.sh
```

This script will:
- Install all Python dependencies from `requirements.txt`
- Download the latest EasyPrivacy tracker list
- Download the Disconnect.me tracker database
- Create the output directory structure

### Step 3: Take Your tool-installed Snapshot
Now that the tool is fully configured, save this state. This is the snapshot you will restore before every experiment.

In VirtualBox:
- Go to **Machine → Take Snapshot**
- Name it `tool-installed`
- Click OK

You now have two snapshots:
- `clean-baseline` — the nuclear option if everything breaks
- `tool-installed` — what you restore before every experiment session

## Sharing the VM With Teammates

Rather than each person going through the full setup independently, one person exports the configured VM and shares it. Everyone else imports it directly.

### Exporting (done by the person who completed setup)
In VirtualBox:
- Go to **File → Export Appliance**
- Select `email-privacy-vm`
- Save as `email-privacy-vm.ova`
- Upload the `.ova` file to the team's shared Google Drive folder

> The `.ova` file will be several gigabytes. Do not put it on GitHub.

### Importing (done by the other three teammates)
- Download `email-privacy-vm.ova` from the shared Google Drive
- Open VirtualBox
- Go to **File → Import Appliance**
- Select the `.ova` file and click Import
- Once imported, the VM is fully configured and ready — no additional setup needed

## Running an Experiment

Each team member runs experiments for their assigned provider across all four phases.

| Team Member | Provider | Phases |
|---|---|---|
| Andre | Gmail | account_creation, idle, active_usage, tracker_test |
| Daniel | Outlook | account_creation, idle, active_usage, tracker_test |
| Rishi | ProtonMail | account_creation, idle, active_usage, tracker_test |
| Ryan | Tutanota | account_creation, idle, active_usage, tracker_test |

### Before Every Experiment Session
**Restore the tool-installed snapshot** — this is non-negotiable. In VirtualBox:
- Go to **Machine → Restore Snapshot → tool-installed**

Then run through the [Pre-Experiment Checklist](#pre-experiment-checklist) before starting any capture.

### Starting a Capture
```bash
chmod +x capture/start_capture.sh
./capture/start_capture.sh
```

You will be prompted for:
1. Which provider (`gmail` / `outlook` / `protonmail` / `tutanota`)
2. Which phase (`account_creation` / `idle` / `active_usage` / `tracker_test`)

The script will start mitmproxy automatically and tell you when it is ready. Open Firefox and begin your experiment.

### Phase-Specific Instructions

**account_creation**
- Start the capture, then navigate to the provider's signup page
- Complete the full account creation flow from start to finish
- Stop the capture once the inbox fully loads for the first time
- Note: create a throwaway account using the format `eptest.[provider]@[domain]`

**idle**
- Log into the inbox, start the capture, then do nothing for exactly **15 minutes**
- Do not click, scroll, or interact with the page at all
- Stop the capture after 15 minutes

**active_usage**
- Log into the inbox and start the capture
- Compose a new email to your team's shared test account with subject line `TEST - [your name] - [date]`
- Send the email
- Open the received reply
- Reply to it
- Stop the capture

**tracker_test**
- Go to https://canarytokens.org and generate a Web Bug / URL token
- Embed the tracking pixel URL in an email body as an `<img>` tag
- Send it to your test inbox on the provider you are testing
- Open the email
- Check whether the canary token fired (you will receive a notification if it did)
- Note in your capture whether a request went out to the canary token domain

## Pre-Experiment Checklist

Run through this before every single capture session. Do not skip steps.

```
[ ] VM restored to tool-installed snapshot
[ ] No browser extensions installed or active in Firefox
[ ] Not logged into any personal accounts in the browser
[ ] Browser proxy is set to 127.0.0.1:8080
[ ] mitmproxy is running and confirmed working
[ ] start_capture.sh has been run with correct provider and phase selected
[ ] Wireshark capture started on the correct network interface
[ ] VPN is turned OFF on your host machine
[ ] No other applications running inside the VM
[ ] You are on a stable network connection
```

> **VPN note:** Always turn off any VPN on your host machine before running experiments. A VPN changes your apparent IP address and can cause providers to behave differently, which would make results incomparable across teammates running on different networks or VPN servers.

## Running Analysis

After completing a capture, run the analysis script to classify all captured traffic:

```bash
python3 analysis/classifier.py \
  --input output/[provider]/[phase]/capture.csv \
  --provider [provider]
```

Example:
```bash
python3 analysis/classifier.py \
  --input output/gmail/account_creation/capture.csv \
  --provider gmail
```

This will produce an `analysis.json` file in the same directory containing:
- Total requests made
- Number of unique domains contacted
- All third-party domains observed
- Breakdown by category (analytics, advertising, fingerprinting, CDN, etc.)
- Any plaintext email addresses detected in request bodies
- Encryption assessment for message content

To run the encryption checker specifically on active usage captures:
```bash
python3 analysis/encryption_checker.py \
  --input output/[provider]/active_usage/capture.csv
```

To generate the full cross-provider comparison report after all four teammates have pushed their results:
```bash
python3 report/generate_report.py
```

This produces `output/final_report.html` which you can open in any browser.

## Important Notes

**On browser extensions:** Do not install any extensions in the VM browser. Extensions make their own network requests which will appear in your captures and contaminate your results.

**On Google's privacy policy:** Gmail does not have a standalone privacy policy. It falls under Google's unified policy at https://policies.google.com/privacy. This is itself a finding — document it. Similarly check whether Outlook has a standalone policy or falls under Microsoft's general privacy statement.

**On encryption verification:** When analyzing ProtonMail and Tutanota captures, message bodies should appear as unreadable ciphertext in mitmproxy even though you have the CA certificate installed. This is because their encryption happens inside the browser in JavaScript before the data reaches mitmproxy. If you can read the message body in plaintext, their end-to-end encryption claim is false. For Gmail and Outlook, message content will be readable in intercepted requests since they use TLS only.

**On domain classification:** The classifier will mark some domains as `unknown_third_party` when they do not appear in the EasyPrivacy or Disconnect lists. These require manual research. Add your findings to `config/manual_classifications.yaml` so the whole team benefits from your research.

**On methodology consistency:** All four teammates must use the same browser (Firefox), the same phase durations (15 minutes for idle), and the same email content for active usage. Any variation between providers introduces confounds that weaken your comparative findings.
