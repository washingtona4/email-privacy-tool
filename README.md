## How This Tool Works

This tool captures and analyzes all network traffic generated by each email provider during four phases of use: account creation, passive idle usage, active email usage, and tracker testing. It works by routing your browser traffic through mitmproxy, which intercepts and logs every HTTP and HTTPS request the provider makes — including requests to third-party services the provider may not disclose.

```
Your Browser → mitmproxy (intercepts + logs everything) → Email Provider's Servers
```

After each experiment, the analysis scripts classify every domain contacted, flag known trackers, quantify metadata exposure, and assess whether encryption claims hold up.

**Everything runs inside a Virtual Machine (VM).** This ensures:
- A clean, identical environment for every experiment
- No contamination from your personal browsing history or background apps
- Full reproducibility across all four team members
- The ability to restore to a known-good state before each test

## VM Setup

> **Skip this section if you received the `.ova` file from a teammate.** This section is only for the person doing the initial setup from scratch.

Do this once. When complete, export the VM as `.ova` and share it with the team so everyone starts from an identical environment.

### Step 1: Download and Install VirtualBox
Go to https://www.virtualbox.org and download the installer for your operating system.

> If you have an Apple Silicon Mac (M1/M2/M3/M4), select **macOS / Apple Silicon hosts**.

### Step 2: Download Ubuntu
Go to https://ubuntu.com/download/desktop and download Ubuntu. Select the **ARM 64-bit** version if you are on Apple Silicon. The file is around 4GB so start this download early.

### Step 3: Create the VM
- Open VirtualBox and click **New**
- Name it `email-privacy-vm`
- Select the Ubuntu ISO you downloaded as the boot disk
- VirtualBox will auto-detect Ubuntu and enable unattended installation
- Set username and password when prompted — remember the password, you will need it
- Assign at least **8GB RAM** and **4 CPU cores** (Firefox becomes unusably slow with less)
- Set disk size to **25GB**
- Click Finish and let Ubuntu install automatically — this takes 10-20 minutes

### Step 4: Install System Tools Inside the VM
Once Ubuntu is installed and you are logged in, open a terminal and run:
```bash
sudo apt-get update
sudo apt-get install -y wireshark tshark python3 python3-pip git curl
```

When prompted during the Wireshark install, select **Yes** to allow non-superusers to capture packets.

### Step 5: Install mitmproxy

> **Important:** Do NOT use `pip3 install mitmproxy` — it will fail with an "externally managed environment" error on newer Ubuntu versions. Use apt instead:

```bash
sudo apt-get install -y mitmproxy
```

Verify it installed correctly:
```bash
mitmdump --version
```

### Step 6: Update PATH
```bash
echo 'export PATH=$PATH:/home/vboxuser/.local/bin' >> ~/.bashrc
source ~/.bashrc
```

### Step 7: Configure Browser Proxy
- Open **Firefox** inside the VM
- Go to Settings → scroll to the bottom → Network Settings → click Settings
- Select **Manual proxy configuration**
- Set **HTTP Proxy** to `127.0.0.1`, Port `8080`
- Check **"Also use this proxy for HTTPS"**
- Click OK

### Step 8: Install the mitmproxy CA Certificate
This is the most critical step. Without it, mitmproxy cannot read HTTPS traffic.

1. Open a terminal and start mitmproxy:
   ```bash
   mitmdump --listen-port 8080
   ```
2. Open Firefox and navigate to `http://mitm.it`
3. Click **Get mitmproxy-ca-cert.pem** under the **Linux** section and save the file
4. In Firefox go to Settings → Privacy & Security → scroll down → Manage Certificates → Authorities tab → Import
5. Select the downloaded certificate file
6. Check **"Trust this CA to identify websites"**
7. Click OK and restart Firefox
8. Verify it works by visiting `https://google.com` — it should load normally with no security warnings, and you should see the request appear in the mitmproxy terminal

### Step 9: Take Your clean-baseline Snapshot
In VirtualBox with the VM running:
- Go to **Machine → Take Snapshot**
- Name it `clean-baseline`
- Click OK

This is your recovery point if anything ever goes wrong.

### Step 10: Clone the Repo and Run Setup
```bash
git clone https://github.com/washingtona4/email-privacy-tool.git
cd email-privacy-tool
chmod +x setup.sh
./setup.sh
```

> **GitHub authentication note:** When cloning, use your GitHub username and a Personal Access Token as the password — not your GitHub account password. Generate one at GitHub → Settings → Developer Settings → Personal Access Tokens → Tokens (classic) → check the **repo** scope → Generate.

### Step 11: Take Your tool-installed Snapshot
Before taking this snapshot:
- Log out of any accounts in Firefox (Gmail, Claude, etc.)
- Clear all browser history and cookies: Firefox Settings → Privacy & Security → Clear Data → check everything → Clear

Then in VirtualBox:
- Go to **Machine → Take Snapshot**
- Name it `tool-installed`
- Click OK

You now have two snapshots:
- `clean-baseline` — the nuclear option if everything breaks
- `tool-installed` — what you restore before every experiment session

### Step 12: Export and Share the VM
- Shut down the VM: `sudo systemctl poweroff -i`
- In VirtualBox go to **File → Export Appliance**
- Select `email-privacy-vm`, click Next
- Save as `email-privacy-vm.ova` — this takes 10-20 minutes
- Upload the `.ova` to the team Google Drive folder
- Share the Drive folder with all teammates

> The `.ova` file will be around 5GB. Do not put it on GitHub.

## Running an Experiment

Each team member runs experiments for their assigned provider across all four phases.

| Team Member | Provider | Phases |
|---|---|---|
| Andre | Gmail | account_creation, idle, active_usage, tracker_test |
| Daniel | Outlook | account_creation, idle, active_usage, tracker_test |
| Rishi | ProtonMail | account_creation, idle, active_usage, tracker_test |
| Ryan | Tutanota | account_creation, idle, active_usage, tracker_test |

### Before Every Experiment Session
1. **Restore the tool-installed snapshot** — Machine → Snapshots → right click `tool-installed` → Restore
2. Start the VM and log in
3. Open a terminal and start mitmproxy:
   ```bash
   mitmdump --listen-port 8080
   ```
4. Run through the [Pre-Experiment Checklist](#pre-experiment-checklist)

### Starting a Capture
Open a new terminal tab and run:
```bash
cd ~/Desktop/email-privacy-tool
./capture/start_capture.sh
```

You will be prompted for:
1. Which provider (`gmail` / `outlook` / `protonmail` / `tutanota`)
2. Which phase (`account_creation` / `idle` / `active_usage` / `tracker_test`)

Once the script starts, open Firefox and begin your experiment. Press **Ctrl+C** when done.

### Phase-Specific Instructions

**account_creation** (~5 minutes)
- Start the capture, then navigate to the provider's signup page
- Complete the full account creation flow from landing on the signup page to the inbox fully loading
- Stop the capture immediately once the inbox loads for the first time
- Use a throwaway account — format: `eptest.[provider]@gmail.com`

**idle** (exactly 15 minutes)
- Log into the inbox, start the capture, then do absolutely nothing
- Do not click, scroll, move the mouse, or interact with the page in any way
- Set a timer and stop the capture after exactly 15 minutes
- Every teammate must use the same 15-minute duration for results to be comparable

**active_usage** (~10 minutes)
- Log into the inbox and start the capture
- Compose a new email to the team's shared test account with subject line `TEST - [your name] - [date]`
- Send the email
- Open a received email
- Reply to it
- Stop the capture — do not do anything else

**tracker_test** (~5 minutes)
- Go to https://canarytokens.org and generate a **Web Bug / URL** token
- Compose an email and embed the token URL as an image tag in the body: `<img src="YOUR_TOKEN_URL">`
- Send it to your own test inbox on the provider you are testing
- Open the email
- Wait 30 seconds
- Check whether the canary token fired — you will receive a notification if it loaded
- Stop the capture

## Pre-Experiment Checklist

Run through this before every single capture session. Do not skip steps.

```
[ ] VM restored to tool-installed snapshot
[ ] mitmproxy is running (mitmdump --listen-port 8080)
[ ] Firefox loads https://google.com without security warnings
[ ] No browser extensions installed or active in Firefox
[ ] Not logged into any personal accounts in the browser
[ ] Browser proxy is set to 127.0.0.1:8080
[ ] start_capture.sh has been run with correct provider and phase selected
[ ] VPN is turned OFF on your host machine
[ ] No other applications running inside the VM
[ ] You are on a stable network connection
```

> **VPN note:** Always turn off any VPN on your host machine before running experiments. A VPN changes your apparent IP address and can cause providers to behave differently, which would make results incomparable across teammates.

## Running Analysis

After completing a capture, run the analysis script. Replace the timestamp with your actual filename:

```bash
python3 analysis/classifier.py \
  --input output/[provider]/[phase]/capture_[timestamp].csv \
  --provider [provider]
```

Example:
```bash
python3 analysis/classifier.py \
  --input output/gmail/account_creation/capture_20260511_093313.csv \
  --provider gmail
```

This produces an `analysis.json` file in the same directory containing:
- Total requests made
- Number of unique domains contacted
- All third-party domains observed
- Breakdown by category (analytics, advertising, fingerprinting, CDN, etc.)
- Any plaintext email addresses detected in request bodies
- Encryption assessment for message content

To run the encryption checker on active usage captures:
```bash
python3 analysis/encryption_checker.py \
  --input output/[provider]/active_usage/capture_[timestamp].csv
```

To generate the full cross-provider comparison report once all four teammates have pushed results:
```bash
python3 report/generate_report.py
```

This produces `output/final_report.html` — open it in Firefox to see the full comparison.

## Pushing Your Results

After completing and analyzing each experiment:

```bash
git add output/
git commit -m "Add [provider] [phase] results"
git push
```

When prompted for a password, use your GitHub Personal Access Token.

Commit after every phase — not all at once at the end. This lets the report generator produce partial comparisons as work progresses and keeps everyone's progress visible.

Raw `.mitm` capture files are excluded from git automatically via `.gitignore`. Only the processed CSVs and `analysis.json` files are committed.

## Important Notes

**mitmproxy must be running for Firefox to work.** Every time you start the VM, run `mitmdump --listen-port 8080` in a terminal before opening Firefox. If Firefox shows "proxy server is refusing connections" this is why.

**Copy/paste between Mac and VM does not work on Apple Silicon.** This is a known VirtualBox limitation. Open this README in Firefox inside the VM and copy commands from there into the terminal using **Ctrl+Shift+V**.

**Restore the snapshot before every experiment — no exceptions.** If you forget and run two experiments back to back without restoring, your second capture will contain leftover cookies and session data from the first, contaminating your results.

**On browser extensions:** Do not install any extensions in the VM browser. Extensions generate their own network requests which will appear in your captures and contaminate results.

**On Google's privacy policy:** Gmail does not have a standalone privacy policy. It falls under Google's unified policy at https://policies.google.com/privacy. This is itself a finding worth documenting. Check whether Outlook also falls under a unified Microsoft policy rather than an email-specific one.

**On encryption verification:** When analyzing ProtonMail and Tutanota captures, message bodies should appear as unreadable ciphertext in mitmproxy even though you have the CA certificate installed. This is because their encryption happens inside the browser in JavaScript before data reaches mitmproxy. If you can read the message body in plaintext, their end-to-end encryption claim is false. Gmail and Outlook message content will be readable since they use TLS only.

**On domain classification:** The classifier will mark some domains as `unknown_third_party` when they do not appear in the EasyPrivacy or Disconnect lists. These require manual research. Add findings to `config/manual_classifications.yaml` so the whole team benefits.

**On methodology consistency:** All four teammates must use the same browser (Firefox), the same phase durations (15 minutes for idle), and the same scripted actions for active usage. Any variation between providers introduces confounds that weaken comparative findings.
